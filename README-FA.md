# Maze for Maze Pro

این نسخه بر پایهٔ بازی اصلی ساخته شده است. هستهٔ تولید ماز و مسیر‌یابی جدا شده، منوها به کامپوننت‌های مستقل تقسیم شده‌اند و لایهٔ ارتباط بلادرنگ و سرور Matchmaking به‌صورت جداگانه اضافه شده‌اند.

## امکانات این نسخه

- حفظ حالت تک‌نفره، کنترل‌ها، زوم، Follow، Torch، Hint، نقشهٔ کوچک و ذخیرهٔ محلی بازی.
- منوی شروع جدید با ۱۰ انتخاب: Free Play و مسابقه‌های ۲ تا ۱۰ نفره.
- منوی جداگانهٔ ۳، ۶ و ۹ هدف پس از انتخاب تعداد بازیکن.
- قفل ترتیبی هدف‌ها: هدف بعدی فقط پس از جمع‌کردن هدف فعلی فعال می‌شود.
- نمایش شمارهٔ هدف‌ها، کم‌شدن فاصلهٔ شمارنده تا هدف و برجسته‌شدن هدف فعال.
- جوی‌استیک در کنترل‌های کناری برای دسکتاپ و تبلت افقی؛ در موبایل همان جایگاه قبلی روی صفحهٔ بازی حفظ می‌شود.
- اتاق جداگانه برای هر ترکیب «تعداد بازیکن + تعداد هدف»، شمارندهٔ واقعی انتظار، ماز مشترک، موقعیت زندهٔ رقبا و برد بر اساس رسیدن اولین بازیکن به همهٔ هدف‌ها.
- هر سرور می‌تواند چندین اتاق مستقل و هم‌زمان بسازد؛ ظرفیت واقعی تابع منابع سرور و پیکربندی میزبانی است.

## آزمون‌های محلی

از ریشهٔ پروژه اجرا کنید:

```bash
npm test
```

این تست‌ها تولید مازهای ۳، ۶ و ۹ هدفه، یکتایی هدف‌ها، دسترس‌پذیری خانه‌ها و سازگاری دیواره‌ها را بررسی می‌کنند.

## اجرای محلی و تست چندنفره (روش پیشنهادی)

**برای تست چندنفره دو مرورگر روی یک سیستم، فقط اجرای `python -m http.server` کافی نیست.** یک سرور جدا برای WebSocket لازم است. برای کم‌کردن خطای پیکربندی، این نسخه در اجرای کامل پروژه، فرانت‌اند را هم از همان سرور Node ارائه می‌کند.

از ریشهٔ پروژه اجرا کنید:

```bash
cd server
npm install
npm start
```

بعد در هر دو مرورگر این نشانی را باز کنید:

```text
http://127.0.0.1:8080/
```

سرور و صفحه اکنون روی همان پورت هستند و بازی در محیط localhost به‌طور خودکار از `ws://127.0.0.1:8080` برای ارتباط استفاده می‌کند؛ نیازی به پرکردن تنظیمات سرور در تست محلی نیست. برای بررسی سرور، این URL را باز کنید:

```text
http://127.0.0.1:8080/health
```

خروجی باید شامل `"status":"ok"` و `"frontendServed":true` باشد. وقتی هر مرورگر باز است، مقدار `onlinePlayers` باید افزایش یابد. پس از انتخاب یک حالت و هدف یکسان، مقدار `waitingPlayers` نیز باید تغییر کند. کنسول ترمینالی که `npm start` در آن اجرا شده، رویدادهای اتصال، صف و شروع اتاق را ثبت می‌کند.

### تست دو نفره به ترتیب

1. مطمئن شوید فقط یک نمونه از سرور روی پورت `8080` فعال است و پنجرهٔ ترمینال باز مانده است.
2. دو مرورگر یا دو پروفایل جدا را به `http://127.0.0.1:8080/` وصل کنید.
3. در هر دو، حالت `2-Player` و سپس هدف `3 Points` را انتخاب کنید.
4. مرورگر اول باید `Waiting players: 1 / 2` را نشان دهد. پس از ورود مرورگر دوم، سرور باید اتاق را بسازد و بازی در هر دو مرورگر با یک ماز مشترک شروع شود.
5. اگر شمارنده تغییری نکرد، `/health` را بررسی و لاگ ترمینال و مقدار Network Status در منو را ثبت کنید.

دو مرورگر روی یک کامپیوتر هر دو می‌توانند از `127.0.0.1` استفاده کنند. برای دستگاه دوم روی شبکهٔ محلی، باید آدرس LAN رایانهٔ میزبان را وارد کنید (مثلاً `ws://192.168.1.20:8080`) و دسترسی پورت را در فایروال مجاز کنید؛ خودِ `127.0.0.1` روی دستگاه دوم به همان دستگاه دوم اشاره می‌کند.

## انتشار آنلاین

GitHub Pages فقط فایل‌های فرانت‌اند را میزبانی می‌کند و خودش قابلیت WebSocket/Matchmaking ندارد. پوشهٔ `server/` را روی یک سرویس میزبانی Node.js جدا منتشر کنید:

- **Root directory:** `server`
- **Build command:** `npm install`
- **Start command:** `npm start`

در سایت نهایی، بخش **Multiplayer server settings** را باز و URL سرور را وارد کنید. اگر سایت با HTTPS منتشر شده، URL سرور نیز باید `wss://...` باشد. URL پس از ذخیره در `localStorage` باقی می‌ماند. مقدار خالی در تنظیمات فقط برای دامنه‌های localhost به سرور محلی `127.0.0.1:8080` برمی‌گردد؛ در سایت عمومی، سرور باید صریحاً تنظیم شود.

### انتشار سرور

پوشهٔ `server/` را روی یک سرویس میزبانی Node.js منتشر کنید:

- **Root directory:** `server`
- **Build command:** `npm install`
- **Start command:** `npm start`

سپس در منوی بازی آدرس WebSocket همان سرویس را وارد کنید. در سایت HTTPS حتماً از نشانی `wss://...` استفاده کنید؛ مرورگرها اتصال ناامن `ws://` را از صفحهٔ HTTPS مسدود می‌کنند. آدرس پس از ذخیره در `localStorage` مرورگر باقی می‌ماند و شمارنده‌ها پس از اتصال به سرور فعال می‌شوند.

## رفتار Matchmaking

- صف‌ها بر اساس تعداد دقیق بازیکنان و تعداد هدف انتخابی جدا می‌شوند؛ برای نمونه، مسابقهٔ `4 players + 6 targets` وارد صف `4:6` می‌شود.
- وقتی تعداد بازیکنان صف به ظرفیت دقیق برسد، سرور یک اتاق مستقل می‌سازد. کاربران اضافی در صف می‌مانند تا گروه بعدی تشکیل شود.
- اولین عضو گروه، ماز را تولید و به سرور ارسال می‌کند؛ سپس همان ماز و نقاط هدف برای همهٔ اعضای اتاق منتشر می‌شوند.
- حرکت و پیشرفت هر بازیکن روی سرور اعتبارسنجی می‌شود. پیشرفت هدف‌ها برای هر بازیکن مستقل است و اولین نفری که هدف‌های ۱ تا ۳/۶/۹ را به ترتیب جمع کند، برنده می‌شود.
- اگر کسی پیش از شروع از اتاق خارج شود، آن گروه لغو می‌شود تا یک مسابقه با تعداد بازیکن ناقص آغاز نشود. خروج هنگام مسابقه به‌عنوان بازیکن قطع‌شده نمایش داده می‌شود.

## محدودیت‌ها و ملاحظات انتشار

- وضعیت اتاق‌ها و صف‌ها در حافظهٔ همان فرایند Node نگهداری می‌شود؛ برای این نسخه یک نمونهٔ سرور کافی است. ری‌استارت سرور صف‌ها و مسابقه‌های جاری را پاک می‌کند.
- «تعداد بی‌نهایت» به معنی پشتیبانی از چندین اتاق مستقل هم‌زمان بدون محدودیت ثابت در کد است، نه ظرفیت فیزیکی بی‌نهایت؛ محدودیت CPU، RAM و شبکهٔ میزبان همچنان برقرار است.
- این پیاده‌سازی برای مسابقهٔ سریع و بدون حساب کاربری طراحی شده است. قبل از انتشار عمومی بزرگ‌مقیاس، rate limit، احراز هویت/مقابله با سوءاستفاده، ثبت وقایع و ذخیره‌سازی مشترک برای چند نمونهٔ سرور را اضافه کنید.

### تنظیم سرور آنلاین Render

در نسخهٔ مستقرشده، نشانی سرور چندنفره در `index.html` در متای `maze-multiplayer-url` تنظیم می‌شود. برای سرویس فعلی مقدار آن باید این باشد:

`wss://maze-78sa.onrender.com`

اگر دامنهٔ Render تغییر کرد، همین مقدار را به‌روزرسانی و دوباره Deploy کنید.
